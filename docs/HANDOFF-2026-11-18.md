## What works in the webpage

The public site has offline replay/import/export and live Web Serial controls.
Use desktop Chrome or Edge with the original SSA program and Python console
disconnected from the port.

- Connection opens the browser port picker directly. The observed adapter is
  Prolific VID `067B`, PID `23A3`, historically COM4.
- Serial settings: **9600 baud, 8N1, no flow control, DTR/RTS on**. Opening the
  port sends no startup command bytes. Interpret measurements only with the
  instrument in **SAE inches/pounds**.
- Start, Continue increment, Home, and Stop request act on **one button click**.
  Movement dialogs, the threshold consent checkbox, and the page-close warning
  were removed at the operator's explicit request. Keep that preference.
- One open connection supports multiple completed tests. A new Start begins a
  fresh graph; Continue appends to the existing incremental graph.
- Exact logs retain all tests in the connection, including setup, attempted and
  completed writes, raw received bytes, step requests, and replies. CSV and chart
  exports describe the current test; complete-session JSON also includes the full
  connection log and raw bytes.
- Browser recovery preserves recordings but is not a guaranteed disk save.
  Download complete-session JSON or the live JSONL log to keep a portable copy.
- No automatic Start, Home, Continue, reconnect, or retry is performed. Busy,
  duplicate-click, incomplete-step, and pending-return guards remain.

The **Test Config fields remain local drafts**. Their Global Max, increment,
cyclic force, and cycle count are not generally applied to the instrument.
The separate live **Set Incremental · 10 lb** action is the one implemented
numeric setup operation.

## Incremental operation and its limitations

The original SSA application's working exchange was captured, then reproduced
in our webpage:

1. Send bare `I`; wait for `I` followed by carriage return.
2. Wait about 400 ms, then send exactly `MI010\r` (six bytes).
3. Start with one bare `T`.
4. Each operator Continue sends another bare `T`, retaining the same test.

There is no verified acknowledgment for the numeric parameter. Setup is labeled
requested, not independently verified. Only the captured **10 lb** setting is
offered. Do not invent other parameter messages.

The first step returns `D\r` and measurements. Resumed steps return `ID\r`
**before** the numeric reading. `ID` alone is not a completed physical pause.
Continue becomes available after a new positive-force reading associated with
the current step; the operator must observe that it has actually paused.
One-click operation is not independent verification of that physical condition.

**Ten-pound selection does not produce precise ten-pound increases.** The
original working capture recorded 57, 132, 176, 214, 249, 286, and 320 lb.
Today's latest browser trial recorded 59, 147, 191, 230, 268, 305, 340, 372,
and 406 lb. Incremental provides operator-controlled pauses, not a lower motor
speed. Several achieved increases exceed the selected increment substantially.

Identical `MI010\r` bytes preceded both failed and successful original-SSA
exchanges, with a power cycle between attempts. The instability is unresolved;
do not assume the message always hangs the board or replay failed bursts.

## Two different force settings

**Incremental 10 lb** requests the nominal size of each step.
**Software stop threshold** is an optional overall stop for the entire test.
Arming it takes one click before Start; it stays active across Continues and is
not automatically rearmed for a new test.

On the first received force at or above the armed threshold, the page sends
exactly one `S`. This does not set a hardware limit or guarantee a maximum force.

- A real **100 lb overall threshold** trial received 0, 47, 70, 94, and 118 lb.
  At 118 lb, our page automatically sent `S`; `TU\r` and then `H\r` followed.
  The actual force peak after the final transmitted reading is unknown.
- In the first browser Incremental trial, **both settings were 10 lb**. Readings
  were 0 and 52 lb, where the overall threshold sent Stop and ended the test.
  That explains the two-reading result; it was not evidence of a serial lockup.
- Other low-load specimens bent or broke with only zero telemetry, including on
  the machine's display. The cause remains unresolved. A first nonzero reading
  of 47 lb rules out a universal rule withholding all readings below 50 or 60 lb.
- Continuous-run records arrived about 70–72 ms apart. Stiff specimens gained
  tens of pounds between records. The webpage preserves the received records;
  it cannot reconstruct measurements the tester never transmitted.

## Home investigation: distinguish the two cases

### Earlier run: Home was blocked in our webpage

The browser trial ending at **264 lb / 0.006 in** sent Stop and received only
`S\r`. No host `H` was transmitted. Our active-test guard blocked Home.

That restriction was corrected in **9f0796a**. Home can now be requested after a
complete positive-force incremental reading, including after an `S` reply.
It sends one `H` and waits for a response, without retrying automatically.

### Latest run: Home was transmitted, but no response followed

The latest saved session contains nine step requests and a final transmitted
reading of **406 lb / 0.011 in**:

| Event | Local time, November 18 | Recorded result |
| --- | --- | --- |
| Stop requested | 5:31:51 p.m. | Host write completed; `S\r` reply |
| Home requested | 5:32:00 p.m. | Host `H` write completed; no subsequent RX before export |
| Session saved | 5:32:09 p.m. | No return/end marker or Home reply recorded |

This time the webpage did not block Home. A completed host write is not proof
that firmware accepted it. The operator reports no commanded return, but an
eventual return using the physical Start button. That button action's timing
and outcome are not present in the saved export.

**Working conclusion:** treat return from an incremental hold as requiring the
physical panel until a reliable serial exit/return sequence is established.
The evidence does not prove an electrical interlock, permanent firmware defect,
or absence of every possible remote-return command. No version query was sent
after the unanswered Home in this recording.

Do not emulate holding the physical Start button by repeatedly sending `T`:
the captured serial meaning of `T` in this state is to advance another increment.
Do not invent abort sequences or clear the pending-return state merely because
time has elapsed. Retained force/displacement readings are not current load
measurements after return, and a Home reply alone is not proof of unloading.

## Observed protocol reference

| Message | Observation and scope |
| --- | --- |
| `V` | Returns `V4.0\r`; useful communication check |
| `H` | Home request; works in some states, unanswered in the latest incremental hold |
| `C` | Continuous selection request; observed `C\r` reply |
| `I` | Incremental selection request; observed `I\r` reply |
| `MI010\r` | Captured 10 lb setup; no separate parameter acknowledgment established |
| `T` | Start a test or advance a paused Incremental test, depending on device state |
| `S` | Stop request; active return observed in some runs, only `S\r` at an incremental hold |
| `D\r` | Initial test-data marker |
| `ID\r` | Observed before a resumed Incremental measurement; exact acronym unverified |
| `dddd,ffff\r` | Displacement = first field / 1000 inches; force = second field in pounds, SAE |
| `TT\r` | Normal test-end marker |
| `TM\r` | Correlated with maximum-force-exceeded display |
| `TU\r`, then `H\r` | Observed stop/return sequence followed by Home report |

## Machine and motor research

- AMT's [company history](https://www.amt-machine.com/history.html) dates the
  predecessor 510C to **1992** and the SSA1000 model introduction to **1998**.
  The production date of this particular unit is unknown.
- Interior photos show a gearmotor, toothed-belt transmission to the central
  shaft, and a controller board. Board/chip date markings are not readable.
  The two visible blue trimmers have unknown functions; do not adjust them as
  presumed speed controls or change calibration.
- The candidate motor is Dayton **4Z062A**. Its original
  [manufacturer manual](https://www.artisantg.com/info/Grainger_Dayton_Electric_4Z062A_Manual_2018425101352.pdf)
  specifies 115 VAC and 14 RPM output at 60 Hz. Exact installed-nameplate
  confirmation is still needed; this does not establish SSA's motor-drive circuit.
- The saved SSA manuals document no loading-speed adjustment. Incremental and
  Cyclic change pause/termination behavior, not a documented motor-speed setting.
  Motor/controller or mechanical-reduction changes would be a separate
  engineering task, not an implemented webpage feature.
- The [manufacturer FAQ](https://amt-machine.com/FAQ.html) describes poor force
  accuracy below 10 lb and plotting starting above 10 lb. We have not established
  an adjustable acquisition threshold or calibrated low-load behavior.
- Maximum breaking-force specification is 1,000 lb. Maximum mechanical travel
  remains unverified; work-area dimensions are not a stroke specification.
